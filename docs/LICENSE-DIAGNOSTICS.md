# 兼容性与合法许可诊断

Legacy Studio 提供**诊断与记录**，不提供许可证恢复、授权绕过、盗版激活或商业资源获取。兼容性建议不能扩大用户对软件、代码、资源或商标的权利。

## 1. 许可证记录状态

| 状态 | 含义 |
|---|---|
| `UNKNOWN` | 没有可核验许可证；默认状态 |
| `USER_DECLARED` | 用户声明许可或授权范围；仍需自行保存证明 |
| `OPEN_SOURCE` | 存在可核验的公开许可证文件或官方来源 |

当前分析器不会仅凭文件名、程序行为或可运行性推断商业软件授权。即使软件已停止维护或原作者失踪，也不自动视为可自由再分发。

## 2. 兼容性诊断

诊断内容包括 PE 架构、.NET/JRE/Electron/Python/Visual C++ 运行库线索、同目录 DLL/OCX 等。每项结论带有证据状态：

- `EVIDENCE`：文件头或目录事实。
- `INFERENCE`：规则推断，需进一步验证。
- `UNKNOWN`：信息不足。
- `VERIFIED`：仅用于可重复验证结果。

建议使用官方运行时、官方安装介质或合法保留副本。不要安装来源不明的 DLL、破解补丁、密钥生成器或所谓“兼容修复器”。

## 3. 独立重建与许可

独立重建只能复用用户提供的**功能规格**，不能复制原软件专有源码、资源、品牌标识或未授权界面素材。生成物应使用自己的名称、代码与资源，并保留 `RECONSTRUCTION.json` 的来源档案哈希与限制。

如果目标是开源软件，应记录其具体许可证、版本、版权声明与再分发义务。开源不等于可以移除署名、混淆许可或忽略 copyleft 要求。

## 4. 用户责任

使用者应自行确认：

- 是否拥有运行、分析、备份和导出数据的权利。
- 是否允许修改、再分发或商用生成物。
- 第三方依赖、字体、媒体和代码片段是否有独立许可证。
- 是否需要在隔离环境或特定旧系统上验证。

项目维护者不提供个案法律意见；遇到不确定许可时，应停止再分发并咨询权利人或许可证专业人士。
