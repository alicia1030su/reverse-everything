## 基线结论

REA 的核心定位是“给 Coding Agent 的统一逆向 MCP 工具层”，而不是本项目的“持久化项目 + 自动流水线 + 重建验证”工作台。官方文档描述：

1. 通过 MCP 和 CLI 暴露等价工具；CLI 与 Agent 共用工作流。
2. 覆盖原生二进制、JavaScript/Electron、.NET、网站、Android、固件、包/资源、HAR、PCAP 等对象；具体能力依赖宿主与 provider。
3. 深度原生分析复用用户已合法安装的 Hopper、Ghidra、IDA 等；静态 JavaScript/.NET 不需要原生引擎。
4. 结果带证据与限制；分析在本地执行，但 Agent 模型供应商有自己的数据政策。
5. 浏览器/运行时观察、进程/文件系统/协议对比、跨层 feature trace 等能力有独立指南与验证轨道。
6. 官方路线图仍列出原生类型/间接调用验证、跨层追踪、运行时观察、移动/固件等计划；计划不等于已交付。

REA 文档中某些高级能力受平台限制。例如 Windows Ghidra 的可用性不能由通用 README 推定；本报告不声称 REA 在 Windows 上已完成与本项目相同的验证。

## 人工仍然必须完成的步骤

1. 确认目标所有权、授权范围与可接受影响。
2. 提供合法取得的客户端、回放记录、会话或测试账号。
3. 复核静态规则候选、模型推断和未知协议字段。
4. 在隔离环境批准运行时行为与主动测试。
5. 判断生成兼容服务的法律、版权、商标与资源分发边界。
6. 对关键结论执行独立复现，而不是只看 AI 摘要。

## 可合法复用的组件

- Playwright / Chrome DevTools Protocol：浏览器采集，Apache-2.0。
- Fastify、React、Vite、TanStack Query、React Flow、Monaco、ECharts：均为宽松开源许可证；以 lockfile 和 license-checker 结果为准。
- `yauzl`：ZIP 中央目录读取，MIT；不解压、不执行条目。
- Node.js `node:sqlite`：本地持久化，Node 22.13+。
- Ghidra：Apache-2.0，可在用户合法安装后作为外部 provider 接入；当前版本未集成。
- OWASP WSTG：CC BY-SA 4.0，仅作为测试分类参考；本项目不复制其规则正文。

## 应重新设计的部分

- 面向普通用户的授权、项目、证据、检查点和导出闭环。
- 输入/工具/模型/验证四层来源标签及结论跳转。
- 本地单用户令牌、SSRF/DNS 固定、同源浏览器采集和不可信内容边界。
- 由证据生成、可启动、可测试的独立兼容服务，而非把模板冒充原始代码恢复。

## 结论

逆向万物不声称比 REA 更强。v0.0.1 选择更窄但可验证的闭环：真实任务、真实证据、可恢复状态、可运行兼容服务和诚实的能力边界。REA 覆盖更广的工具层是后续 provider 集成与协议/网页研究的重要参考。
