# AI、授权与数据边界

## 核心原则

**用户授权先于模型建议，工具证据先于模型结论。** 模型可以分类、总结或提出计划建议，但不能自行扩大授权、修改预算、调用未注册工具或宣布验收成功。

## 目标契约

执行前用户需确认结构化契约，内容包括：

- 用户目标、输入、分析目标、授权范围。
- 允许操作与禁止操作。
- 预期输出、必需交付物、验收标准。
- 时间、磁盘、内存、模型调用、Token、费用和修复预算。
- `local-only` 或 `remote-approved` 数据共享。
- 已知限制、未知项和需要用户参与的事项。

未授权目标分析会进入 `BLOCKED`，不会创建虚假计划或子任务。

## 默认允许与禁止

| 允许（在契约与工具权限内） | 默认禁止 |
|---|---|
| 读取任务工件 | 任意 shell |
| 写入任务工件 | 执行未知代码 |
| 授权后只读分析目标 | 写入任务工作区之外 |
| 授权后执行分析器 | 网络外传 |
| 授权且允许构建时执行 allowlist 构建 | 未经同意调用远程模型 |
| 静态站点生成、规则测试、打包、独立验收 | 修改原始输入、绕过访问控制 |

## 数据共享

- 默认 `local-only`。
- 本地 Provider 指向 loopback 时不需要远程共享同意，但仍受预算、Schema 和工具权限约束。
- 非本地 Provider 必须使用 HTTPS，并在保存或测试前获得显式同意。
- 同意按 Provider ID 记录；更换端点或数据范围时应重新评估。
- 远程同意不等于允许发送所有材料；只应发送任务必需且已获授权的数据。

## 密钥

- API Key 由宿主应用的 SecretStore 保存，Provider 配置只保留 `apiKeyRef`。
- 前端和列表 API 不返显 Key，只返回 `hasApiKey`。
- 网络错误会脱敏已知密钥和 Bearer token。
- 不要将 Key 写入提示词、交付包、日志、截图或命令行历史。

## 模型输出

- 结构化输出必须通过 JSON/Schema 校验。
- 意图解析结果仍只是建议，不能替代授权。
- 模型生成内容属于 `INFERENCE`，工具结果属于 `EVIDENCE`，可复现测试才可能属于 `VERIFIED`。
- 缺少证据时保持 `UNKNOWN`，不得补写成功结论。

## 用户应何时拒绝授权

- 目标不属于你或授权范围不清。
- 要求绕过登录、验证码、付费、DRM、反作弊或访问控制。
- 要求执行来源不明的程序、脚本或构建命令。
- 要求把敏感材料发送到未审查的远程服务。
- 要求删除原始材料、修改系统设置或安装驱动。
- 要求把 Mock、规则型结果或模型自述冒充真实验收。

## 当前未验证项

真实远程 Key E2E、模型驱动重规划、多智能体上下文隔离、长期记忆权限继承均尚未完成验收。相关能力不得在未验证前描述为已可用。完整声明见 [DISCLAIMER.md](../DISCLAIMER.md) 与 [安全模型](SECURITY-MODEL.md)。
